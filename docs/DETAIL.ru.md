# Как это работает

Эта страница описывает, как dsh-paste-image помещает почти любое изображение — даже с неверно указанным типом — в поле ввода DeepSeek Harness при вставке или перетаскивании. Она опирается на [`how-it-works.md`](how-it-works.md) и отражает текущую реализацию: вывод PNG / JPEG / WebP, переключатели конвертации для каждого формата и настройки в `localStorage` браузера.

## Обзор потока

```text
вставка / перетаскивание (фаза захвата)
        |
        v
  handle(event, data)
        |  нет файлов, больше maxFiles или нет кандидата-изображения -> выход, родной путь
        |  preventDefault() + stopPropagation()
        v
  для каждого файла-кандидата -> normalize(file)
        | sniff(bytes) -> реальный формат
        | родной формат и совпадение объявления -> null (файл не трогается)
        | объявление типа пусто -> перемаркировать File без перекодирования
        v
  toCanvas()
        | XPM       -> decodeXpm()
        | SVG       -> loadSvg() + растеризация через <img>
        | BMP / DIB -> createImageBitmap(), резерв decodeBmp()
        |              (встроенные данные JPEG/PNG извлекаются первыми)
        | ICO / CUR -> createImageBitmap(), резерв — самая большая PNG-запись
        | остальное -> createImageBitmap()
        v
  canvasOf()   длинная сторона ограничена maxSide (по умолчанию 4096)
        v
  encodeCanvas()  canvas.toBlob(profile.mime[, quality])
        v
  new File(name.<ext>, тип берётся из фактического blob.type)
        v
  reroute(files) -> синтетическое DragEvent('drop') на [data-composer-card]
```

## 1. Фаза захвата

Плагин слушает `paste` и `drop` на `document` в режиме захвата (`addEventListener(..., true)`). Фаза захвата идёт от `document` вниз к цели, поэтому плагин видит событие раньше собственного обработчика поля ввода; если произошла конвертация, он может вызвать `preventDefault()` до того, как поле прочитает `clipboardData`.

## 2. Предварительные проверки и условия пропуска

`handle()` возвращается сразу, не перехватывая событие, если:

- Главный выключатель выключен (`enabled === false`): обработчики остаются установленными и начинают работать сразу после повторного включения.
- Событие уже несёт метку `REROUTED`: это исключает рекурсию, когда плагин снова видит своё же синтетическое событие.
- Нет файлов или их больше `maxFiles` (по умолчанию 8, настраивается 1–8): вся партия идёт родным путём, без частичной конвертации.
- Ни один файл не является кандидатом-изображением: объявленный тип должен начинаться с `image/` либо имя файла должно заканчиваться на расширение изображения; вставка обычного текста никогда не совпадает.
- Отсутствуют конструкторы `DataTransfer` / `DragEvent` или не найдена карточка поля ввода (`[data-composer-card]`): плагин отпускает событие, и родной путь браузера продолжает работать.

Каждый файл-кандидат конвертируется в своём `try/catch`; при ошибке исходный файл сохраняется.

## 3. Определение по магическим байтам

`sniff()` читает первые байты и определяет реальный формат по сигнатуре: PNG, JPEG, GIF, WebP (RIFF + WEBP), BMP (`BM` или DIB без файлового заголовка `BITMAPINFOHEADER`), TIFF (II/MM), XPM (`/* XPM */`), AVIF / HEIC (бренд `ftyp`), ICO/CUR (`00 00 01 00` / `00 00 02 00`), SVG (начинается с `<` и содержит `<svg` в первом КиБ). Если совпадений нет, возвращается `null`. DIB без файлового заголовка сначала проверяется по длине заголовка, знакам ширины/высоты и глубине цвета, чтобы случайные бинарные данные не принять за изображение.

## 4. Пропуск без изменений

`normalize()` читает только первые 1024 байт заголовка, чтобы решить, трогать ли весь файл:

- Переключатель конвертации для этого формата выключен: исходный файл проходит, даже не читая полные байты.
- Родной тип (PNG/JPEG/WebP/GIF), чьё объявление совпадает с реальными байтами: проходит после чтения 1 КиБ заголовка. Реальные скриншоты поэтому полностью сохраняют байты, метаданные и анимацию.
- Объявление типа пусто: байты переупаковываются в `File` с обнаруженным типом (без перекодирования), чтобы пройти белый список хоста.
- Объявление не совпадает с реальными байтами (например, BMP заявляет PNG): файл конвертируется и перекодируется в выбранный формат вывода.

При конвертации расширение заменяется на фактическую кодировку (`shot.xpm` -> `shot.png`); перемаркированные родные файлы сохраняют своё расширение. Таблица MIME-псевдонимов (`image/jpg`, `image/x-png`, `image/svg+xml` и др.) сначала нормализует написания, чтобы исправные файлы не перекодировались зря.

## 5. Декодирование и кодирование

Пути декодирования: XPM использует встроенный декодер; SVG растеризуется через `<img>` (у Chromium нет `createImageBitmap()` для SVG-блобов); остальное идёт в `createImageBitmap()`, при этом BMP использует резерв `decodeBmp()` или извлекает встроенный JPEG/PNG, а ICO — резерв на самую большую PNG-запись. Размер масштабируется по формуле `scale = min(1, maxSide / длинная сторона)`; маленькие изображения остаются без изменений.

Кодирование выполняет `encodeCanvas()`: PNG без потерь и без параметра качества; JPEG сначала накладывается на непрозрачный белый фон (прозрачные пиксели не становятся чёрными), WebP сохраняет прозрачность, и оба получают `quality`. Итоговый тип берётся из фактического `blob.type` браузера, с резервом на PNG, если он не распознан.

## 6. Перенаправление

`reroute()` помещает конвертированные файлы в `DataTransfer` и отправляет синтетическое событие `drop` (с неперечислимой меткой `REROUTED`) на реальную карточку поля ввода. Это использует тот же путь вложений, что и ручное перетаскивание, без закрытого API поля; если карточка не найдена, событие не отправляется.

## 7. Обработка ошибок и журналы

Конвертация выполняется для каждого файла в `try/catch`. Успех пишет строку вроде `image/xpm -> image/png 1440x900`; ошибка пишет `keep original (image/bmp): ...` и сохраняет исходный файл — один плохой файл никогда не блокирует остальные, синтетический drop всё равно происходит, а результатом становится обычная ошибка хоста, а не тишина. Записи идут через `console.debug`, поэтому консоль браузера должна быть установлена в Verbose.

## 8. Настройки и страница конфигурации

Настройки живут только в `localStorage` браузера (ключ `dsh-paste-image.settings.v1`; в приватном режиме или при отключённом хранилище используется копия в памяти, и вставка продолжает работать). Их можно изменить на странице конфигурации плагина или через `api.getSettings()` / `api.applySettings(patch)` / `api.resetSettings()`.

| Настройка | По умолчанию | Значение / диапазон | Действие |
| --- | --- | --- | --- |
| `enabled` | `true` | boolean | Главный выключатель; при выключении вставка идёт родным путём |
| `maxFiles` | `8` | целое 1–8 | Макс. число файлов в партии; при превышении вся партия проходит без изменений |
| `maxSide` | `4096` | целое 512–8192 | Ограничение длинной стороны конвертированных изображений |
| `outputFormat` | `png` | `png` / `jpeg` / `webp` | Формат вывода конвертации (PNG, если формат не поддерживается) |
| `quality` | `0.92` | 0.1–1 (2 знака) | Качество кодирования JPEG / WebP; отключено в форме при выборе PNG |
| `convertXpm` | `true` | boolean | Конвертировать ли XPM |
| `convertBmp` | `true` | boolean | Конвертировать ли BMP / DIB |
| `convertSvg` | `true` | boolean | Конвертировать ли SVG |
| `convertIco` | `true` | boolean | Конвертировать ли ICO / CUR |
| `logConversions` | `true` | boolean | Выводить ли отладочные журналы конвертаций |

Форма конфигурации содержит указанные выше флажки, выпадающий список формата вывода и три числовых поля; черновики живут в состоянии компонента и записываются только при нажатии «Сохранить»; «Восстановить по умолчанию» возвращает значения таблицы.

## 9. Ограничения и неподдерживаемые случаи

- **HEIC / TIFF**: сигнатуры распознаются, но не декодируются (встроенного декодера нет), файлы остаются как есть.
- **XPM**: не поддерживаются форматы заголовка XPM1/XPM2 и цветовые ключи, отличные от `c`; имена палитры, не являющиеся допустимыми CSS-цветами (например, состоящее из двух слов `light gray`), выводятся непрозрачным чёрным; `None` полностью прозрачен.
- **BMP / DIB**: поддерживаются длины заголовка 12/40/52/56/64/108/124, глубины 1/4/8/16/24/32, сжатие BI_RGB / RLE8 / RLE4 / BITFIELDS / ALPHABITFIELDS, встроенные JPEG/PNG и растровые изображения сверху вниз; изображения более 64 Ми пикселей отклоняются до выделения памяти. 32-битный альфа-канал, полностью состоящий из нулей, считается непрозрачным.
- **ICO / CUR**: поддерживаются только иконки с PNG-записью (берётся самая большая по площади); иконки только с DIB и курсоры не поддерживаются.
- **Родные форматы**: PNG, JPEG, WebP и GIF с объявлением, совпадающим с реальными байтами, никогда не перекодируются.
- **Сравнение размера**: фото с JPEG/WebP примерно на 82 % меньше; скриншоты интерфейса часто меньше с PNG. См. [замеры форматов вывода](output-formats.md).

## 10. Принципы проектирования

Байты важнее меток; синхронная отмена в фазе захвата; PNG как формат вывода по умолчанию (в белом списке, без потерь, универсален в Chromium); синтетический drop вместо закрытого API; без процесса хоста и сторонних декодеров.
